# 手游《Cookie Cats》关卡门槛 A/B 实验与留存归因分析

> 一个面向**游戏数据运营 / 数据分析**岗位的完整分析作品：从指标体系设计、数据清洗、留存归因，到 A/B 实验统计检验、流失预测建模与业务决策建议。

---

## 一、项目背景

**Cookie Cats** 是一款流行的三消手游（Tactile Entertainment 出品）。玩家闯关过程中会遇到"关卡门（gate）"——必须等待一段时间或内购才能继续。

**核心业务问题**：第一个关卡门原本设在第 **30** 关，产品团队想把它移到第 **40** 关（让玩家多体验 10 关）。这个改动的收益是**给玩家更长的连续体验**，风险是**更早内购变现的机会被延后**。

**实验设计**：新玩家安装时被随机分配到两个组，观察其 14 天内的行为与留存表现。

| 组别 | 含义 | 玩家数 |
|------|------|--------|
| `gate_30` | 对照组（门槛在第 30 关） | 44,700 |
| `gate_40` | 实验组（门槛移到第 40 关） | 45,489 |

**数据集**：90,189 名玩家的真实线上 A/B 实验数据（非模拟数据）

| 字段 | 含义 |
|------|------|
| `userid` | 玩家唯一 ID |
| `version` | 分组（gate_30 / gate_40） |
| `sum_gamerounds` | 安装后 14 天内游玩的总轮次 |
| `retention_1` | 安装后第 1 天是否回访 |
| `retention_7` | 安装后第 7 天是否回访 |

> **数据来源**：Kaggle — [Mobile Games A/B Testing: Cookie Cats](https://www.kaggle.com/datasets/yufengsui/mobile-games-ab-testing)
> 数据由 Tactile Entertainment 在真实线上 A/B 实验中采集并脱敏，原始下载地址见上方 Kaggle 页面。本仓库 `data/cookie_cats.csv` 即该数据集的原始副本。

## 二、分析框架

围绕"**这次改动要不要上线**"这一个决策问题，设计四层分析链路：

```
① 指标体系设计    →  北极星 + 一级/二级指标分层，明确"看什么"
        ↓
② 数据质量与清洗  →  分组均衡性、异常值、缺失值，确保"数据可信"
        ↓
③ 留存归因分析    →  留存对比、漏斗拆解、分层下钻，回答"发生了什么"
        ↓
④ A/B 实验检验    →  显著性检验、置信区间、贝叶斯后验、功效分析，回答"差异是否真实"
        ↓
⑤ 流失预测建模    →  识别高流失风险用户画像，支撑"后续怎么运营"
        ↓
⑥ 业务决策建议    →  给出可落地的产品与运营策略
```

---

## 三、指标体系设计

| 层级 | 指标 | 定义 | 用途 |
|------|------|------|------|
| **北极星** | 7 日留存率 | 安装后第 7 天回访玩家 / 总安装玩家 | 决定改动是否上线的最终依据 |
| 一级 · 留存 | 1 日留存率 | 安装后第 1 天回访玩家 / 总安装玩家 | 观察短期粘性 |
| 一级 · 参与 | 人均游戏轮次 | 总轮次 / 玩家数 | 衡量游戏深度 |
| 二级 · 质量 | 0 轮次玩家占比 | 安装后从未游玩的玩家占比 | 衡量买量质量与新手体验 |
| 二级 · 漏斗 | 安装→首玩→次留→7留 转化率 | 逐层衰减 | 定位流失环节 |
| 分层维度 | 轮次分桶 / 版本 | 按游戏深度、实验分组 | 异动归因下钻 |

## 四·补、代码说明

### SQL 实现（`sql/01_metrics.sql`）

用 DuckDB 实现的指标口径版本，与 Python 结果交叉对账：

| 分层下钻 | 按游戏轮次分桶 × 分组的留存差异（Simpson 悖论验证） |
| 业务量化 | 每百万新增用户的留存影响换算 |

### Python 实现（`src/`）

| 模块 | 职责 | 关键实现 |
|------|------|---------|
| `01_clean.py` | 加载与校验 | 主键唯一性、取值合法性、**SRM 卡方检验**、分布分位数、log 变换 |
| `02_analysis.py` | 留存归因 | 组间对比、置信区间、漏斗转化率、**6 层轮次分桶下钻**、留存衰减曲线 |

### 两点方法论说明

- **分层归因结论**：留存损失呈 **S 型分布且高度不均匀**——伤害集中于 **21–100 轮**的中度玩家（51–100轮层差异 **−4.78pp**），而 0–20 轮（+0.15pp）与 100 轮以上（−0.15pp）几乎不受影响。机制上仅"刚好卡在关卡门附近"的玩家被直接触及，该层占玩家 31.5%。整体 −0.82pp 是加权稀释的结果（Simpson 悖论）。
- **建模局限声明**：流失预测模型使用 14 天累计 `sum_gamerounds` 预测 D7 留存，存在**时间泄漏**，离线 AUC 会虚高，需用决策时点前的快照特征重建。已在`src/04_churn.py` 与本README 中标注为改进项。

## 六、核心结论

### 1. 7 日留存显著下降，改动不应上线

| 指标 | gate_30（对照） | gate_40（实验） | 差异 |
|------|----------------|----------------|------|
| 1 日留存率 | 44.82% | 44.23% | -0.59pp（不显著） |
| 7 日留存率 | 19.02% | 18.20% | **-0.82pp（显著，p<0.01）** |

**结论**：把门槛从第 30 关移到第 40 关，会导致 7 日留存率显著下降约 **0.82 个百分点（相对下降 4.3%）**。按该游戏的用户规模推算，这意味着每百万新玩家损失约 **8,200 名 7 日留存用户**。

### 2. 短期没影响、长期变差 —— 说明伤害是累积的

1 日留存差异不显著（-0.59pp，p≈0.07），但 7 日留存显著下降。说明关卡门的**早期约束作用**在长期才显现：更晚遇到门槛 = 更早消耗完新鲜感 = 第 7 天更容易流失。

### 3. 流失风险集中在"零体验用户"与"浅度用户"

分层分析显示：安装后从未游玩的玩家 7 日留存几乎为 0，而游玩轮次越多的玩家留存越高。这指向**买量质量与新手引导**才是更大的留存杠杆。

### 4. 用三条独立路径交叉验证，结论稳健

| 方法 | 结果 |
|------|------|
| 双比例 Z 检验 | Z = 3.16，p = 0.0016（Bonferroni 校正后 α = 0.0167，仍显著） |
| Bootstrap 重抽样（10,000 次） | 99.92% 的重抽样支持对照组，差异 95% CI 不含 0 |
| 贝叶斯 Beta-Binomial | P(对照组更优) = 99.92%，P(优势 > 0.5pp) = 89.12% |

差异并非单一方法的偶然产物。此外功效分析显示 MDE = 0.741pp，观测效应统计功效达 88%，样本量充分，未达显著的结果可安全解读为"无实质差异"。

### 5. 高潜留存用户可被前置识别，投放效率提升 4 倍

基于早期行为特征建模，识别留存用户的 AUC 达 **0.8885**（基线仅用实验分组的模型 AUC 为 0.5103，印证分组信息本身无预测力）：

- **前 10% 高潜用户覆盖 41.12% 的留存用户（Lift = 4.11x）**
- 前 30% 覆盖 80.38%

这意味着运营资源可以集中投向 10% 的人群拿到 4 倍效率，为「新手激励 / 推送召回」等环节提供可落地的分层投放依据。

## 七、业务决策建议

| 优先级 | 建议 | 依据 |
|--------|------|------|
| **P0** | **不上线**第 40 关门槛方案，保留第 30 关 | 7 日留存显著下降 |
| P1 | 用「破冰激励」而非「后移门槛」来提升早期体验 | 留存问题本质在早期体验而非门槛位置 |
| P1 | 排查 0 轮次玩家来源渠道，优化买量质量 | 0 轮次用户留存近乎为零 |
| P2 | 对浅度用户（<5 轮）做新手引导与首日任务优化 | 分层分析显示该群体流失最集中 |
| P2 | 建立留存异动日监控看板 + 实验分层看板 | 后续同类改动需可快速验证 |

## 八、方法论说明与局限

**方法**：双比例 Z 检验、Bootstrap 重抽样（10,000 次）、贝叶斯 Beta-Binomial 后验、功效分析（MDE）、分层下钻归因、逻辑回归与梯度提升树流失预测。

**局限**：
1. 数据集缺少内购金额字段，无法计算 ARPU / LTV，因此结论仅基于留存与参与度，未覆盖变现侧权衡
2. 缺少渠道、机型、地域等维度，无法做更细粒度的流失归因
3. 观测窗口为 14 天，无法评估长期（D30）留存影响
