# 第一部分：从小白到看懂这份 A/B 实验报告

## 第0 章 · 先建立一个直觉：A/B 实验到底在干什么

### 0.1 一句话定义

**A/B 测试 = 用随机对照实验来回答"我这个改动到底有没有用"。**

它解决的是产品团队每天都在吵的一个问题：

| 不做实验的做法                          | 做实验的做法                                             |
| -------------------------------- | -------------------------------------------------- |
| 老板说："把关卡门槛从 30 关挪到 40 关，让玩家玩得更久" | 让一部分玩家玩新版，一部分玩旧版                                   |
| 上线后看整体留存，发现跌了                    | 但**不知道**是改动导致的，还是季节波动、买量素材变化、某个渠道崩了                |
| 结论："感觉没用，回滚"                     | 结论："在 9 万人的随机样本下，改动使 7 日留存下降 0.82pp，p=0.0016，拒绝上线" |

**核心区别在于：随机分组。** 这是 A/B 实验的立命之本。

### 0.2 为什么"随机"两个字这么重要

假设你不用随机，而是让**运营主动挑选**：

- 组长放给一群老玩家（他们本来就爱玩，留存高）
- 组长放给一群新玩家（他们本来就留不住）

这时候你观测到的"新版留存更高"，其实是"老玩家留存更高"，跟改动毫无关系。这种混淆叫**选择偏差（Selection Bias）**，是所有非实验分析的通病。

随机分组的作用，就是让两组在**所有维度上**（年龄、机型、渠道、地域、付费意愿……）尽可能相似。差异越小，两组的对比就越干净，差异就越可能来自"改动"本身。这叫**随机化 / 随机对照（RCT）**。

> 你的英国硕士背景里，RCT 就是你在 Clinical Trial 里学的那套方法论，A/B 实验只是把它搬到 App 增长上。医学试验分 treatment / control，App 实验也叫实验组 / 对照组，一模一样。

### 0.3 本项目的业务背景（必须能背下来）

- 游戏：Cookie Cats，Tactile Entertainment 出的三消手游
- 机制：玩家闯关时会遇到"关卡门（gate）"——必须**等待若干小时**或**内购**才能继续
- 现状：第一个关卡门设在第 **30** 关
- 提案：挪到第 **40** 关，让新手多玩10 关
- 争议点：
  - **支持方**：多10 关体验 = 更长的连续游戏 = 更好留存
  - **反对方**：更早触达付费墙 = 内购机会延后 = 变现受损
- 所以这个实验本质上在做一个**权衡（trade-off）**：留存 vs 变现

| 组别        | 含义                 | 玩家数    | 占比     |
| --------- | ------------------ | ------ | ------ |
| `gate_30` | 对照组 Control（现状）    | 44,700 | 49.57% |
| `gate_40` | 实验组 Treatment（新方案） | 45,489 | 50.43% |

分组比例 1:1，样本量差异在预期内（随机波动）。

### 0.4 数据字段说明（只有4 个字段，但足够做完整分析）

| 字段               | 含义             | 类型   | 我的备注                            |
| ---------------- | -------------- | ---- | ------------------------------- |
| `userid`         | 玩家唯一 ID        | int  | 主键，唯一性校验用                       |
| `version`        | 分组标记           | str  | `gate_30` / `gate_40`，这是**自变量** |
| `sum_gamerounds` | 安装后 14 天内总游戏轮次 | int  | **因变量**之一，衡量参与深度                |
| `retention_1`    | 安装后第 1 天是否回访   | bool | **因变量**，短期留存                    |
| `retention_7`    | 安装后第 7 天是否回访   | bool | **因变量**，北极星指标                   |

**只有 4 个字段能做什么？** 说实话，做不了完整的因果分析（没有 ARPU、没有渠道、没有机型）。但**足够回答"这次改动该不该上线"这个决策问题**。这一点在面试里要主动说——**局限意识比假装全面更能加分**。

## 第 1 章 · 第一步：指标体系设计（为什么先定指标，而不是先跑数据）

### 1.1 什么是指标体系

指标体系 = 一套分层的、带因果逻辑的度量规则，避免"上线后该看哪个数"的争吵。

本项目设计的层级：

| 层级      | 指标             | 定义（口径）                           | 在决策中的角色            |
| ------- | -------------- | -------------------------------- | ------------------ |
| **北极星** | 7 日留存率         | retention_7 = True 的玩家数 / 组内总玩家数 | **最终拍板依据**         |
| 一级 · 留存 | 1 日留存率         | retention_1 = True /组内总玩家数       | 观察短期粘性，判断影响是短期还是长期 |
| 一级 · 参与 | 人均游戏轮次         | sum_gamerounds 均值                | 参与深度（改动直接影响）       |
| 二级 · 质量 | 0 轮次玩家占比       | sum_gamerounds = 0 的玩家占比         | 买量质量与新手体验          |
| 二级 · 漏斗 | 安装→首玩→次留→7留    | 逐层转化率                            | 定位流失发生在哪一环         |
| 分层维度    | 轮次分桶 / version | 按游戏深度交叉分组                        | 异动归因下钻             |

### 1.2 为什么 7 日留存是北极星，而不是 1 日留存或轮次

面试必答题。三个层次的理由：

1. **业务价值对齐**：留存是游戏业务真正的生命线，一次获客成本（CAC）需要后续多次变现才能收回，留存不行一切都是亏的。7 日留存是行业内公认的"新手期质量"标尺——一个用户 7 日内不流失，后续留存曲线会陡峭很多。
2. **抗噪声**：留存是二值变量（0/1），方差小、分布稳定。轮次是长尾 heavy-tailed 分布（均值 52，中位数只有 17，差了3 倍），单个大R玩家能让均值剧烈波动。**指标要选"稳定且能代表业务价值"的，而不是"看起来业务相关"的**。
3. **可归因**：1 日留存只能反映"当天体验好不好"，7 日留存才能反映"新用户是否真的形成了回访习惯"——这才是长期价值的代理变量。

**但我要主动补充一个真实的缺陷**（这就是加分项）：

> 7 日留存作为北极星是不完整的，因为本实验的争议核心之一是**变现**。数据里**没有内购金额字段**，无法计算 ARPU / LTV。所以我的结论只能是"从留存侧看不该上线"，无法说"综合留存+变现后不该上线"。严格讲，一个完整的判断应该是：
>
> **上线条件**：Δ留存 × 生命周期价值 > ΔARPU × 转化提升，否则不上线。  
> 数据缺 ARPU，所以只能给出单边结论。**这个局限我在报告里明确写了。**

### 1.3 关键：北极星必须唯一，且必须"可决策"

很多新人会犯的错：把 10 个指标都当北极星，最后汇报时"留存涨了、轮次跌了、ARPU 没数据"，不知道听谁的。

正确做法：定唯一北极星 + 其他指标降级为"辅助解释"。本项目里：

- 拍板只看 7 日留存
- 其他指标只用来说"**为什么会这样**"

## 第 2 章 · 第二步：数据质量与清洗（面试最容易被问"你数据怎么保证可信"）

### 2.1 做了什么检查

在 `src/01_clean.py` 里，我做了这几件事：

| 检查项             | 方法                     | 结果                      |
| --------------- | ---------------------- | ----------------------- |
| 行列完整性           | shape                  | 90,189 行 × 4 列，无缺失      |
| 主键唯一性           | `userid` duplicated 检查 | 0 重复                    |
| 分组取值合法性         | `value_counts`         | 仅 gate_30 / gate_40，无脏值 |
| **样本量均衡性（SRM）** | 两组人数比例                 | 49.57% vs 50.43%，无异常    |
| 二值指标合法性         | `retention_1/7` 取值     | 仅 True/False            |
| 轮次分布            | 直方图 + 分位数              | 右偏长尾，中位数 17，P90 = 135   |
| 极端值             | 分位数截尾分析                | 需关注但不删除（见下）             |

### 2.2 【技术八股必背】什么是 SRM（Sample Ratio Mismatch）

**定义**：A/B 实验中，两组的实际样本量比例显著偏离预设分流比例。这是**实验系统出bug 的第一号信号**，比指标异常更致命。

**卡方检验**：

```
χ² = Σ (O_i - E_i)² / E_i          df = 1
```

本例：预期各 50,050.5 人，实际 44,700 vs 45,489  
χ² = (1937.5²/50050.5)×2 ≈ **0.15**，df=1，p ≈ 0.70 → **通过**，分流系统健康。

**什么情况会触发 SRM**：

1. 分流代码有bug（比如 `userid % 2` 在某个 ID 段失效）
2. 客户端与服务端分流不一致（同一用户两端拿到不同版本）
3. 埋点丢失集中在某一组
4. 过滤逻辑有偏（某组数据被join 掉了）

**面试话术**：*"在做任何指标比较前，我会先做 SRM 检验。本例中两组比例 49.57%:50.43%，卡方检验 p=0.70，分流健康。否则后面的显著性检验全部无效。"*

### 2.3 【技术八股】极端值处理：为什么不删

轮次分布是典型长尾：

| 组       | 均值    | 中位数  | P90   |
| ------- | ----- | ---- | ----- |
| gate_30 | 52.46 | 17.0 | 135.0 |
| gate_40 | 51.30 | 16.0 | 134.0 |

**均值 52 > 中位数 17**，说明被大量小值玩家拉高了少数大R 的贡献。

处理原则（三选一）：

1. **不删**（本项目选择）：因为轮次是**行为数据的真实观测**，删掉会引入选择偏差，而且A/B 实验的核心是对比，异常值如果两组分布相近，对**组间差异**影响很小
2. **截尾winsorize**：把超出 P99 的值压到 P99
3. **变换**：取 log（本项目的"游玩深度 log(轮次+1)"特征就做了这个）

**面试话术**：*"我没有删异常值。理由有两点：一是 A/B 实验关注的是组间差异，两组异常值分布相近时对差异估计影响有限；二是删数据会引入选择偏差。改用 log 变换 + 分位数（均值/中位/P90）来描述分布，并对非正态指标改用 Mann-Whitney U 检验。"*

### 2.4 【技术八股】Mann-Whitney U vs t 检验

轮次均值差1.16轮，p=0.0502，**卡在显著性边界**。这里有个陷阱：

- 若用 t 检验（假设正态）：p ≈ 0.0502，勉强不显著
- 若用 Mann-Whitney U（不假设分布）：检验的是**分布位置**而非均值，对长尾数据更稳健

**Mann-Whitney U 的原假设**：两组的分布相同（即随机标签与分组无关）。它比较的是**秩（rank）**，本质上是"随机抽一个实验组玩家和一个对照组玩家，谁的轮次更多"的概率。

> **它回答的问题不是"均值差多少"，而是"实验组玩家的轮次整体上是否倾向于更高"。**

本例 U = 1,024,331,250，p = 0.0502，处在边界。**我的解读**：均值下降 1.16 轮（-2.26%）方向上确实是实验组更差，但证据不足以在 95% 水平下断言显著。这是一个**诚实的不显著结论**，而不是硬凑显著性。

## 第 3 章 · 第三步：留存归因分析（从"有差异"到"为什么"）

### 3.1 整体留存对比

| 指标      | gate_30 | gate_40 | 绝对差         | 相对差        | 判定               |
| ------- | ------- | ------- | ----------- | ---------- | ---------------- |
| 玩家数     | 44,700  | 45,489  | —           | —          | —                |
| 1 日留存   | 44.82%  | 44.23%  | -0.59pp     | -1.34%     | 不显著（p=0.074）     |
| 7 日留存   | 19.02%  | 18.20%  | **-0.82pp** | **-4.51%** | **显著（p=0.0016）** |
| 1→7 存活率 | 33.32%  | 32.34%  | -0.98pp     | -2.94%     | —                |
| 人均轮次    | 52.46   | 51.30   | -1.16       | -2.26%     | 边界不显著            |
| 首玩率     | 95.67%  | 95.48%  | -0.19pp     | —          | 不显著              |

**一句话解读**：改动对**第 1 天**几乎没影响，但对**第 7 天**有稳定的负面影响。

### 3.2 【核心洞察】短期无影响、长期变差，说明什么

这是整个项目**最有业务含金量的一条结论**。

```
D1: -0.59pp, p=0.074 → 不显著
D7: -0.82pp, p=0.0016 → 显著
```

**推断逻辑**：门槛从 30 关后移到 40 关，玩家的"新鲜感消耗速度"变了。前 1 天大部分玩家根本还没打到第 30 关（人均 51轮，很多人卡不到），所以**门槛位置对 D1 完全没有影响**；但到了第 7 天，玩家的新鲜感已经被前移的体验节奏消耗掉一部分，**回访意愿下降**。

**业务翻译**：关卡门的作用不是"卡住玩家"，而是**制造一个回访动机**（"我的体力还没攒满，回去看看"）。把门槛后移，等于**把这个回访动机往后推了 10 关的距离**，对短期没损失，但削弱了长期回访粘性。

> 面试话术：*"这里我做了一个关键的时间维度拆解。D1 不显著、D7 显著，说明这不是'体验变差'的即时反应，而是'回访动机被削弱'的累积效应。如果只是产品体验变差，D1 就会立刻掉。这个区分决定了后续的解法方向。"*

### 3.3 漏斗拆解：定位流失环节

| 环节      | gate_30         | gate_40         | 差       |
| ------- | --------------- | --------------- | ------- |
| 安装      | 100.00%（44,700） | 100.00%（45,489） | —       |
| → 首玩    | 95.67%（42,763）  | 95.48%（43,432）  | -0.19pp |
| → 次日留存  | 44.82%（20,034）  | 44.23%（20,119）  | -0.59pp |
| → 7 日留存 | 19.02%（8,502）   | 18.20%（8,279）   | -0.82pp |

**读漏斗的正确姿势**：看**每一层的相对衰减率**，而不是绝对人数。

| 环节转化率   | gate_30 | gate_40 |
| ------- | ------- | ------- |
| 首玩 → D1 | 46.85%  | 46.32%  |
| D1 → D7 | 42.44%  | 41.15%  |

**两个环节的转化率都在实验组更低**——说明伤害不是集中在某一步，而是**贯穿整个漏斗的持续泄漏**。

### 3.4 【重点】分层下钻：伤害不是均匀分布的

这是我认为**整个分析里最有价值的部分**，也是面试时最能体现"数据分析深度"的地方。

我把玩家按**游戏深度（sum_gamerounds）**&#x5206;成 6 桶，看每层的7 日留存差异：

| 轮次分桶         | 用户数（总） | gate_30 D7 | gate_40 D7 | 差异 pp     | 解读          |
| ------------ | ------ | ---------- | ---------- | --------- | ----------- |
| 0 轮          | 3,994  | 0.83%      | 0.63%      | -0.20     | 几乎全流失，差异可忽略 |
| 1-5 轮        | 20,723 | 1.29%      | 1.44%      | **+0.15** | 实验组略好（噪声）   |
| 6-20 轮       | 25,085 | 5.03%      | 4.75%      | -0.28     | 轻微负面        |
| **21-50 轮**  | 17,575 | 16.07%     | 14.56%     | **-1.51** | **明显负面**    |
| **51-100 轮** | 10,427 | 38.09%     | 33.31%     | **-4.78** | **最严重**     |
| 100 轮以上      | 12,385 | 71.39%     | 71.24%     | -0.15     | 顶饱和，无差异     |

**关键发现**：

1. **S 型分层曲线**：浅度玩家（0-20 轮）和重度玩家（100 轮+）几乎不受影响，**伤害全部集中在"中度玩家"（21-100 轮）**。
2. **业务解释**：0-20 轮的玩家**还没打到关卡门**（第 30 关），门槛后移对他们无影响；100 轮+的玩家**早已通过关卡门进入后期内容**，门槛后移反而给了他们更长的连续体验，无损。**只有"刚好卡在关卡门附近"的 21-100 轮玩家，是被后移的门槛直接影响的人**。
3. **反直觉的发现**：21-100 轮这个群体占全部玩家的 **31.5%**（28,002 人），却贡献了绝大部分留存损失。
4. **Simpson 悖论的影子**：整体差异 -0.82pp，而 51-100 层的差异是 -4.78pp。因为**各层权重不同 + 高留存层本身差异接近 0**，整体差异被稀释。这是**加权平均掩盖局部效应**的典型案例。

**如果我只能讲一个洞察，就是这个。**

> 面试话术：*"整体看差异只有 0.82pp，好像很小。但分桶后发现它是 S 型的——只集中在 21到 100 轮的中间玩家身上，重度玩家完全不受影响。这个洞察直接把产品建议从'调整关卡门'细化成'针对21-100 轮玩家设计破冰激励'，因为其他层不需要动。"*

### 3.5 【技术八股】辛普森悖论（Simpson's Paradox）

**定义**：分组数据中都成立的结论，在汇总时不成立。原因：**分组权重差异掩盖了组内关系**。

经典例子：某大学 A 专业男生录取率 90%、女生 10%，B 专业反转，汇总后女生录取率更高。

**在本项目中的体现**：

- 层内：51-100 轮层差异 **-4.78pp**（强负面）
- 汇总：**-0.82pp**（弱负面）
- 原因：gate_40 组在100 轮+ 层占比略高（13.83% vs 13.64%），而高留存层差异 ≈ 0

**处理方法**：

1. **分层分析**（本项目采用）
2. **加权归因**：把总差异拆解为"层内效应 (within)" + "权重效应 (between)"，即**Simpson 分解**

**面试话术**：*"我判断总差异被稀释属于辛普森悖论，所以我不满足于总体的显著性，而是做了6 层交叉，用Simpson 分解确认总效应主要来自 21-100 轮的层内效应，而不是各层用户占比变化。分层分析是应对辛普森悖论最标准的手段。"*

## 第 4 章 · 第四步：A/B 实验统计检验（项目技术核心）

这一章是**面试八股的重灾区**，我按"从基础到进阶"讲。

### 4.1 为什么不能直接比较均值，差多少就是多少

因为存在**抽样误差**。即使两个组**真实留存率完全相同**，由于随机性，观测到的差异也**大概率不为 0**。

举例：两组真实留存都是 20%，各抽 44,700 人，观测差异可能在 ±0.4pp 内随机波动。这不是 bug，是统计的固有性质。

**所以我们需要一套规则，回答："观测到的差异，有多大概率只是随机噪声？"** 这就是显著性检验。

### 4.2 【核心八股】假设检验的完整逻辑

```
原假设 H0: p_treat = p_control      （改动无效，两组留存率相同）
备择假设 H1: p_treat ≠ p_control    （改动有效）

1. 假设 H0 为真，计算在 H0 成立的前提下，
   观测到当前数据（或更极端数据）的概率 = p 值

2. 决策规则：
   p ≤ α (0.05) → 拒绝 H0 → 差异显著 → 结论：改动有影响
   p >  α (0.05) → 不能拒绝 H0 → 结论：证据不足

3. 关键：p 值不是"原假设为真的概率"！
```

### 4.3 【最容易错】p 值到底是什么

**p 值的准确定义**：

> 在**原假设成立**的前提下，观察到**当前这么极端或更极端**结果的概率。

**它不是**：

- ❌ "原假设为真的概率"（这是最常见的误解）
- ❌ "结论出错的概率"

**正确理解示例**：  
本例 p = 0.0016 的含义是：**假如两组留存率其实完全一样，那么在 9 万人的样本下，还能观测到 0.82pp 以上差异的概率只有 0.16%。**

因为这么低，所以"H0 为真"这个假设被强烈抵触，我们拒绝它。

### 4.4 【核心八股】第一类错误与第二类错误

| 名称                | 定义           | 概率符号     | 业务含义（A/B实验）                           |
| ----------------- | ------------ | -------- | ------------------------------------- |
| **第一类错误**（弃真、α错误） | H0 为真，却拒绝 H0 | α = 0.05 | **假阳性**：改动其实无效，但被判为有效 → **错误上线，伤害用户** |
| **第二类错误**（取伪，β错误） | H0 为假，却未拒绝   | β = 0.20 | **假阴性**：改动其实有效，但被判为无效 → **错失机会**      |

**两条错误是不对称的**，A/B 实验的默认策略是**宁枉勿纵**（宁可漏掉真效果，也不误上无效改动），因为：

- 假阳性的代价是**全量用户受损**（不可逆）
- 假阴性的代价只是**少赚一点**（可逆）

这就是为什么 α 普遍取 0.05甚至更严（0.01），并且要配合**多重比较校正**。

> 面试话术：*"第一类错误的代价是非对称的。Retention 掉 0.82pp 是全量 9 万玩家不可逆的损失，而漏掉一个正向改动的代价只是少赚。所以我选择保守的 α=0.05 并额外做 Bonferroni 校正到 0.0167，宁可漏过不可错杀。"*

### 4.5 【核心八股】显著性 ≠ 重要性（p 值陷阱）

**这是最高频的面试追问，也是本项目实际遇到的问题。**

7 日留存：p = 0.0016，高度显著；差异 0.82pp。  
1 日留存：p = 0.0744，不显著；差异 0.59pp。

**陷阱**：假设有个实验差异 5pp，p = 0.06。另一个差异 0.1pp，p = 0.001。

- 第一个：业务上极重要，统计上刚好没过线
- 第二个：统计上极显著，业务上完全无意义

**解决方案：三个指标一起看**

| 指标                 | 作用    | 回答什么问题       |
| ------------------ | ----- | ------------ |
| **p 值**            | 统计显著性 | "差异是不是噪声？"   |
| **效应量（Cohen's h）** | 效应大小  | "差异有多大？"     |
| **置信区间**           | 精度    | "真实差异的合理范围？" |

**本项目的 Cohen's h**：

```
h = 2 × arcsin(√p₁) − 2 × arcsin(√p₂)
```

| 指标    | Cohen's h | 效应量标签 | 解读    |
| ----- | --------- | ----- | ----- |
| 7 日留存 | 0.0211    | 可忽略   | < 0.2 |
| 1 日留存 | 0.0119    | 可忽略   | < 0.2 |


**这里有一个必须诚实承认的矛盾**：

> 效应量 Cohen's h = 0.0211 在统计学上是"可忽略"的小效应，**但在这个业务场景下，0.82pp 的 7 日留存下降是完全不可接受的**——因为 7 日留存是北极星指标，且直接乘上千万级用户量就是 8,200 人/百万量级的损失。
>
> 结论：**统计显著性回答"是不是真的"，但真正的决策依据是"业务效应是否超过可承受阈值"。** 在北极星指标上，任何显著的负向都直接否决，无论效应量多小。

> 面试话术：*"这里有个统计学和业务判断的分歧我需要说明：Cohen's h = 0.021 属于可忽略的小效应，但从业务看，7 日留存是北极星指标，0.82pp 的下降在百万级流量下就是 8,200 个留存用户。所以我的决策逻辑是——北极星指标上，显著即否决，不看效应量大小。效应量在这里的作用是辅助判断幅度，而不是否决业务红线的依据。"*

### 4.6 【核心八股】置信区间怎么读（最实用的技能）

本例 7 日留存差异的 95% CI：**[0.312pp, 1.328pp]**

**正确读法**：*"我们 95% 确信真实的留存率差异落在 0.31pp 到 1.33pp 之间。"*

**四种情况与决策**：

| CI 形态            | 含义       | 决策            |
| ---------------- | -------- | ------------- |
| 完全在 0 右侧         | 显著正向     | 上线            |
| **完全在 0 右侧（本例）** | **显著负向** | **不上线**       |
| 跨 0，宽度很窄         | 无差异，精度高  | 确认无实质差异       |
| 跨 0，宽度很宽         | 数据不足     | **加长实验，别下结论** |

**CI 宽度的价值**：

- 本例 CI 宽度 = 1.328 - 0.312 = **1.016pp**，相对于差异 0.82pp，宽度还是偏大（约为差异的 1.24 倍）
- 说明**样本量虽大但效应本身很小**，估计精度有限
- 对比 1 日留存：CI = [-0.058, 1.239]，**宽度 1.3pp，跨 0**，且宽度约为差异的 2.2 倍 → 精度更差

> **加分表达**：*"CI 跨 0 不代表'两组一样'，只代表'我们无法区分'。要区分这三者，必须报告 CI 的宽度和相对差异的倍数。"*

### 4.7 【核心八股】双比例 Z 检验的数学原理（本项目主方法）

**适用场景**：两组独立的比例（如留存率），样本量足够大（n·p·(1-p) > 10）。

**Step 1：合并标准误（pooled SE）**

在 H0 成立下，两组共享同一个真实比例 p，用**合并估计**：

```
p̂ = (x₁ + x₂) / (n₁ + n₂)

SE_pooled = √[ p̂(1 - p̂) × (1/n₁ + 1/n₂) ]
```

代入本例：

```
p̂ = (8502 + 8279) / (44700 + 45489) = 16781 / 90189 = 0.18608

SE_pooled = √[ 0.18608 × 0.81392 × (1/44700 + 1/45489) ]
          = √[ 0.151475× 4.4348e-5 ]
          = √[ 6.7175e-6 ]
          = 0.0025918
```

**Step 2：Z 统计量**

```
diff = p₁ − p₂ = 0.190203 − 0.181986 = 0.008217

Z = diff / SE_pooled = 0.008217 / 0.0025918 = 3.164
```

**Step 3：双尾 p 值**

```
p = 2 × (1 − Φ(|Z|)) = 2 × (1 − Φ(3.164)) = 2 × 0.000777 = 0.00155
```

**Step 4：置信区间（注意：这里用非合并标准误）**

```
SE_diff = √[ p₁(1−p₁)/n₁ + p₂(1−p₂)/n₂ ]
CI = diff ± 1.96 × SE_diff
```

**为什么 CI 用非合并 SE 而 Z 检验用合并 SE？**

这是一个高频深挖点：

- **Z 检验**做的是**假设检验**，H0 成立时两组共享参数，所以用 **pooled SE**（减小方差，提升检验力）
- **置信区间**是对**真实差异**的无偏估计，参数不在 H0 假设下，所以用 **unpooled SE**（更保守、更准）

若偷懒用同一个 SE 算 CI，会低估区间宽度，导致过度自信。

### 4.8 【核心八股】为什么还要做卡方检验

卡方检验是**同一张2×2 表格的另一种检验方法**，它在数学上等价于双比例 Z 检验。

|      | 不显著           | 显著                |
| ---- | ------------- | ----------------- |
| Z 检验 | 7日: 否 / 1日: 否 | 7日: **是** / 1日: 否 |
| 卡方检验 | 7日: 否 / 1日: 否 | 7日: **是** / 1日: 否 |

**Z 检验 vs 卡方检验的对比**：

| 维度    | 双比例 Z 检验      | 卡方独立性检验                        |
| ----- | ------------- | ------------------------------ |
| 统计量   | Z = diff / SE | χ² = Σ(O−E)²/E                 |
| 分布    | 标准正态          | 卡方（df = 1）                     |
| 关系    | χ² = Z²       | 完全等价                           |
| 样本要求  | 大样本           | 大样本（期望频数 ≥5）                   |
| 连续性校正 | 不需要           | 默认有，本项目用 `correction=False` 关闭 |

本例：χ²_p = 3.164² = 10.01，p = 0.00155，**与 Z 检验完全一致**。

**为什么要做？**

1. **交叉验证**：两条数学路径得出同一结论，降低实现 bug 的风险
2. **教学与可读性**：卡方检验可直接用于 2×2 之外的更复杂列联表

> 面试话术：*"卡方和 Z 检验在 2×2 表上数学等价（χ² = Z²），我同时跑是为了交叉验证实现逻辑，没有偏差。另外卡方可以扩展到多维列联表，比如分层后做 Cochran-Mantel-Haenszel 检验。"*

### 4.9 【核心八股】Mann-Whitney U 检验（用于非正态的连续指标）

轮次数据右偏严重，均值检验不稳健，改用**秩和检验**。

**核心思想**：把两组数据合并、按数值从小到大排序（排名），比较两组排名之和。

```
U = R₁ − n₁(n₁+1)/2
```

**零假设**：两组的分布相同 → 秩之和的期望是 n₁n₂/2

**大样本近似**：

```
Z = (U − μ_U) / σ_U,  μ_U = n₁n₂/2
σ_U = √[ n₁n₂(n₁+n₂+1) / 12 ]
```

**读法**：*"P(实验组玩家的轮次 > 对照组玩家轮次) ≈ U/(n₁n₂) = 0.4998，即两组的轮次高低几乎不可区分。"*

**适用条件**：两组独立、样本量足够大（≥30）、**分布形状相似但位置可能不同**（本例满足）。

**与 t 检验的对比**：

| 维度   | t 检验    | Mann-Whitney U  |
| ---- | ------- | --------------- |
| 检验对象 | 均值差     | **分布位置 / 随机优势** |
| 分布假设 | 正态      | 不假设正态           |
| 稳健性  | 差（长尾敏感） | 好               |
| 解读   | "均值差多少" | "随机抽取谁更大"       |

### 4.10 【核心八股】多重比较校正（Why Bonferroni）

**问题（"分析师的诅咒"）**：如果你测了 20 个指标，即使**全部无效**，也几乎必然有 1 个"显著"。

**推导**：单个检验 α=0.05，误报概率 5%。20 个检验**全部无效时至少一个显著**的概率：

```
P(至少一个假阳性) = 1 − (1 − 0.05)^20 = 1 − 0.358 = 64.2%
```

**Bonferroni 校正**：

```
α_corrected = α / m
本例 α = 0.05，m = 3 个指标（1日留存、7日留存、人均轮次）
α_corrected = 0.05 / 3 = 0.01667
```

**结果**：7 日留存 p = 0.00155 < 0.01667 → **仍然显著，结论稳健**

**Bonferroni 的缺点与替代方案**：

| 方法                          | 强度             | 说明                              |
| --------------------------- | -------------- | ------------------------------- |
| **Bonferroni**              | 最保守（FWER 控制）   | 单点调整，可叠加                        |
| **Holm-Bonferroni**         | 略松于 Bonferroni | 逐步降序比较，**同样控制 FWER**            |
| **Benjamini-Hochberg (BH)** | 最松             | 控制 **FDR**（错误发现率），指标多时更常用       |
| **BH 判据**                   | —              | 取 p\_(k) ≤ k/m·α 的最大 k，前 k 个均显著 |

> 面试话术：*"本项目测了 3 个指标，未校正时 D1 的 p=0.074 距离 0.05 只差 0.024，很危险。Bonferroni 校正到 0.0167 后，D7 的 p=0.00155 依然显著，说明核心结论对校正方法稳健。指标更多时我会用 BH 控制 FDR，因为 BH 的统计效力更高。"*

### 4.11 【核心八股】MDE 与统计功效（分析型数据分析师的必备技能）

**核心问题**：*"我的样本量够吗？"*

**MDE（Minimum Detectable Effect，最小可检测效应）**：在当前样本量下，有 80% 把握能检测到的**最小真实差异**。

**统计功效（Power）**：真实存在差异时，能正确检测出来的概率。标准要求 **≥ 80%**。

**双比例检验的功效公式**：

```
n = [ (z_{1-α/2} + z_{1-β})² × (p₁(1−p₁) + p₂(1−p₂)) ] / (p₁ − p₂)²
```

**Power 的组成**：

```
Power = P(拒绝 H0 | H0 为假)
      = 1 − β
      = 1 − P(未拒绝 H0 | H0 为假)
```

**提高功效的四个杠杆**：

| 杠杆              | 原理          | 代价         |
| --------------- | ----------- | ---------- |
| **加大样本量**       | SE ∝ 1/√n   | 成本线性上升     |
| 提高 α（0.05→0.10） | 更易拒绝 H0     | **假阳性风险↑** |
| 降低 MDE 要求       | 容忍更小差异      | 灵敏度↑，特异性↓  |
| **减少组内方差**      | 用 CUC（方差缩减） | 实验设计复杂     |

**方差缩减技术（CUC）**：方差减少 50% 相当于**样本量翻倍**。

| 技术        | 原理                           |
| --------- | ---------------------------- |
| **CUPED** | 用实验前协变量（如历史 ARPU）预测 Y，残差方差更小 |
| **分层随机化** | 先按关键维度分层，再层内随机               |
| **方差剔除**  | 从结果中剔除方差估计，不增加实验负担           |

**本项目结果解读**：

| 指标        | MDE     | 观测效应 h | 实际功效      | 结论                     |
| --------- | ------- | ------ | --------- | ---------------------- |
| **7 日留存** | 0.741pp | 0.0211 | **88.4%** | 效应 > MDE，功效充足，**样本量够** |
| **1 日留存** | 0.933pp | 0.0119 | 42.8%     | 效应 < MDE，**样本量不够**     |

**这是本项目最重要的方法论亮点之一**：

> 1 日留存不显著，**有两个完全不同的解释**：
>
> 1. 真的没有差异（CI跨 0）
> 2. 有差异，但样本量不足以检测出来（功效不足）
>
> **功效分析帮我们区分了这两种情况**：D1 的功效只有 42.8%，远低于 80% 标准，所以"D1 不显著"**不能被解读为"改动对 D1 无影响"**。正确说法&#x662F;*"本研究无法检测到 D1 的差异"*。
>
> 而 D7 功效 88.4%，样本量充分，所以 D7 的显著结论**可靠**。

> 面试话术（重点）：*"这是我项目里最想强调的方法论。不显著≠无差异。D1 的功效只有 42.8%，说明这个设计的样本量根本不足以检测 0.59pp 这样的微小差异，所以 D1 不显著只能解读为'证据不足'，不能解读为'改动对 D1 无害'。相反 D7 功效 88.4%，D7 的显著结论才是可信的。所以在数据充足的主指标上得出的否定结论才是可靠的。"*

### 4.12 【进阶】Bootstrap：为什么需要分布无关的方法

**参数化检验的痛点**：Z 检验假设"样本均值服从正态分布"。虽然 CLT（大数定律）让它在大样本下近似成立，但：

- 轮次这种长尾数据收敛慢
- 中位数、分位数等**非均值统计量**无法用 Z 检验

**Bootstrap 思想（Efron, 1979）**：**把数据当成分布的唯一来源**，通过重抽样模拟采样分布。

**流程**：

```
1. 有放回地从对照组抽 n₁ 个 → 算 diff*
2. 有放回地从实验组抽 n₂ 个 → 算 diff*
3. 重复 10,000 次 → 得到 diff* 的经验分布
4. 用经验分布估计置信区间与 P 值
```

**置信区间构造**：

```
CI = [Quantile_{2.5%}(diff*), Quantile_{97.5%}(diff*)]
```

**本例结果**：

```
mean_diff = 0.83pp
CI95= [0.325, 1.328] pp     → 不含 0，显著
P(对照组更优) = 99.92%
```

**Bootstrap 的三种用途**：

| 用途    | 构造方式                                      |
| ----- | ----------------------------------------- |
| 求 CI  | 百分位法 / BCa法                               |
| 求 p 值 | **null bootstrap**：先把数据按 H0 变换使其均值为0，再重抽样 |
| 任意统计量 | 中位数、偏度、分位数……均可                            |

**注意事项**：

- ⚠️ 只能给CI，**给不了 p 值**（除非做null bootstrap）
- ⚠️ 有偏样本时**BCa** 比百分位法更准
- ⚠️ 计算量比参数化方法大 100~1000 倍（10,000 次重抽样 ≈ 90 万行操作）

> 面试话术：*"Bootstrap 的核心价值是不依赖任何分布假设。我的轮次数据右偏严重（均值52、中位数17），对均值做 Z 检验本身就脆弱，Bootstrap 能直接对中位数、分位数做区间估计。局限是只能给置信区间不能直接给 p 值，要 p 值必须做 null bootstrap，而且计算量大。"*

### 4.13 【进阶】贝叶斯 A/B 测试：把结论翻译成概率

**频率派的困境**：

| 场景        | 频率派输出     | 业务方的问题      |
| --------- | --------- | ----------- |
| 差异显著，效应极小 | p = 0.001 | "所以到底该不该上？" |
| 差异不显著     | p = 0.35  | "所以是不是可以上？" |

**频率派只回答"差异是否为 0"，不回答"效应有多大"和"我该做什么决策"。**

**贝叶斯的优势**：直接输出**决策所需的概率**。

**建模**：

**共轭先验 + 二项似然**（比例型指标的最经典组合）：

```
先验:      p ~ Beta(α, β)              本项目用 Beta(1,1) 弱信息先验
似然:      k 次成功 / n 次试验 → 二项分布
共轭性:    Beta(α,β) + Binomial(k,n) → Beta(α+k, β+n−k)

后验:      p | data ~ Beta(α+k, β+n−k)
```

**共轭先验的本质**：**Beta 分布的均值和方差可以直接从两个数字推出，无需积分**

```
Beta(α, β):
  均值 E[p] = α / (α + β)
  方差 Var[p] = αβ / [(α+β)²(α+β+1)]
```

**本例后验**：

| 组       | 成功 k  | 失败 n−k | 后验 Beta           | 后验均值    |
| ------- | ----- | ------ | ----------------- | ------- |
| gate_30 | 8,502 | 36,198 | Beta(8503, 36199) | 19.021% |
| gate_40 | 8,279 | 37,210 | Beta(8280, 37211) | 18.201% |

**蒙特卡洛采样**：从两个后验各抽 200,000 个样本，计算逐对差异的分布。

**输出结果（业务语言）**：

| 指标            | 数值                | 业务含义                 |
| ------------- | ----------------- | -------------------- |
| **P(对照组更优)**  | **99.92%**        | 有 99.92% 的把握第 30 关更好 |
| P(差异 > 0.5pp) | 89.12%            | 88% 把握损失超过 0.5 个百分点  |
| 95% 可信区间      | [0.312, 1.327] pp | 与频率派 CI 几乎一致         |

**关键洞察**：

> **频率派 CI [0.312, 1.328] ≈ 贝叶斯可信区间 [0.312, 1.327]**
>
> 两条路径给出几乎相同的结果，说明结论**极其稳健**。而贝叶斯多给了两个直接可用于决策的概率。

**为什么本例两者一致？**

因为**样本量极大（4.5 万人/组）+ 弱信息先验 Beta(1,1) 的影响被数据淹没**。

> **Laplace 法则**：数据量足够大时，**先验几乎不影响后验**。  
> `Beta(1,1) + Binomial(8502, 44700)` ≈ `Beta(8503, 36199)`，先验的1 被 8,502 完全支配。

**什么时候贝叶斯优势明显？**

| 场景              | 优势体现                        |
| --------------- | --------------------------- |
| **样本量小**        | 先验主导，能避免"小样本给出极端结论"         |
| **多指标 / 多变体**   | 层次模型可做部分汇聚（partial pooling） |
| **连续实验 / 流式决策** | 可序贯检验，不像频率派必须等固定样本量         |
| **需要决策概率**      | 直接输出 P(胜)，无需解读 p 值          |

**风险：Beta-Binomial 的局限**：

1. **不适用于连续指标**：轮次这类连续变量需用 **Normal-Inverse-Gamma** 共轭对
2. **不适用于非负偏态分布**：轮次长尾，应考虑 **Gamma-Poisson** 或对数变换
3. **需要独立同分布假设**：有网络效应（玩家互相影响）时不成立
4. **共轭先验必须正确指定**：观测数据不该选弱信息先验，会产生underflow 问题

> 面试话术：*"贝叶斯的价值在于把统计结论翻译成决策语言。频率派说 p=0.0016，PD 听不懂也不需要懂；贝叶斯说'有 99.92% 把握第 30 关更好'，PD 一句话就能做决策。同时我的贝叶斯 CI 和频率派 CI 几乎一致（[0.312,1.328] vs [0.312,1.327]），这是结论稳健的最强证据。局限是 Beta-Binomial 只适用于二项型比例指标，轮次这类连续长尾指标需要Normal-Inverse-Gamma 或 Gamma-Poisson。"*

### 4.14 【进阶】三法交叉验证的方法论意义

| 方法        | 假设         | 输出     | 若假设失效会怎样     |
| --------- | ---------- | ------ | ------------ |
| Z 检验      | 大样本 + 正态近似 | p 值、CI | p 值偏保守/偏激进   |
| Bootstrap | 无分布假设      | CI、分位数 | 只能给 CI，无 p 值 |
| 贝叶斯       | 显式先验       | 决策概率   | 后验依赖先验选择     |

三法结论一致 = **结论对方法选择不敏感** = 稳健。

> 这是本报告最有说服力的论证结构：**不是用一种方法证明一个结论，而是证明这个结论无法被任何一种方法推翻。**

## 第 5 章 · 第五步：流失预测建模（从分析到应用）

### 5.1 建模的商业问题

决策层问："既然 gate_30 更好，那**我们在有限资源下，应该优先帮哪批玩家？**"

答案：**识别高潜留存用户，定向投放激励资源。**

### 5.2 Model A 设计：因果链的关键设计

| 模型          | 特征                | AUC        | 结论             |
| ----------- | ----------------- | ---------- | -------------- |
| **Model A** | 仅 `version`（实验分组） | **0.5103** | 分组本身**几乎无预测力** |

**AUC = 0.51 ≈ 随机（0.5）的意义**：

> 证明"玩家属于 gate_30 还是 gate_40"这个信息，**几乎无法预测谁会留存**。
>
> 但我们前面已经证明分组会**因果性地**影响留存。这两件事不矛盾：
>
> - 分组对**总体**留存率有因果影响（0.82pp）
> - 但组内每个人的留存概率高度重叠，**无法从分组推断个体**
> - 这正是**群体效应 ≠ 个体预测**的体现
>
> **这个设计是刻意做的**：它作为"零信息基线"，证明后续 0.888 的 AUC 完全来自**行为特征**而非实验分组这个泄漏变量。

> 面试话术：*"Model A 是我的基线设计，它只用了实验分组，AUC 0.51 说明分组信息几乎不含留存信号。这样做有两个目的：一是验证 0.888的 AUC 不是来自 version 这个泄漏变量；二是证明分组的因果效应是群体级的，无法用于个体预测。这是严谨的建模思路——先立一个零信息基线。"*

### 5.3 Model B 特征工程

**7 个特征**：

| 特征                | 类型         | 含义                |
| ----------------- | ---------- | ----------------- |
| `version_gate_40` | 二值         | 实验分组（1 = gate_40） |
| `retained_1`      | 二值         | 是否次日留存            |
| `played_any`      | 二值         | 是否曾游玩（≥1 轮）       |
| **`log_rounds`**  | 连续（log 变换） | 游玩深度              |
| `rounds_gt_20`    | 二值         | 是否 > 20 轮         |
| `rounds_gt_50`    | 二值         | 是否 > 50 轮         |
| `bucket_ord`      | 有序         | 游玩深度等级 0-5        |

**为什么做 log 变换**：原始轮次右偏（均值52，中位数17），log 压缩长尾使其接近正态，**同时保持单调性**（不改变模型可学的信号）。

**⚠️ 极其重要的局限（面试必被追问）**：

> **`sum_gamerounds` 是 14 天累计值，而标签是 7 日留存 —— 存在时间泄漏（Temporal Leakage）。**
>
> 也就是说：用"7 天累计轮次"预测"第 7 天是否留存"，实际上把第 7 天之后的行为也用进去了。
>
> **真实生产环境中的正确做法**：只用**决策时点之前**的行为预测。  
> 例如"预测 D30 留存"只使用前 14 天的特征。
>
> **我在报告中明确标注了这一局限**，并在面试中主动说明。这比藏起来好——面试官问出来时，你已经准备好了答案，反而显得更专业。

| -------------- | ---------- | ------ | -------- | --------- | ------ | ------ | ------------- |
| A ·仅分组         | 0.5103     | 0.1893 | 0.8140   | 0.000     | 0.000  | 0.000  | 0.5056±0.0044 |

2. **CV AUC 与训练 AUC 差距极小**（0.8886 vs 0.8885）→ **无过拟合，泛化稳定**
3. **Accuracy = 0.8713 是个陷阱！**

### 5.5 【技术八股陷阱】Accuracy 的无用性

**类不平衡问题**：

```
正样本（7日留存）率 = 18.61%
负样本（流失）率     = 81.39%
```

**全猜负样本的准确率 = 81.39%**，比模型的 87.13% 只低 5.7pp，但**信息量为零**。

**混淆矩阵（Model B3）**：

|                  | 预测留存       | 预测流失        |
| ---------------- | ---------- | ----------- |
| **实际留存（4,197）**  | TP = 2,130 | FN = 2,065  |
| **实际流失（75,992）** | FP = 836   | TN = 75,517 |

**为什么必须用 PR-AUC 而不是 ROC-AUC**：

| 指标         | 定义                  | 问题                                          |
| ---------- | ------------------- | ------------------------------------------- |
| ROC-AUC    | TPR vs FPR          | **FPR 分母极巨大**（75,992），误报 836 个让 FPR 仅涨 1.1% |
| **PR-AUC** | Precision vs Recall | **直接聚焦误报成本**，适合不平衡场景                        |

**极端例子**：如果负样本有 100 万人，即使 FP 高达 10 万，FPR 也只有 10%，ROC-AUC 看起来很高，但 Precision 已经崩塌。**PR-AUC 才诚实。**

**Precision = 0.7181 的业务解读**：

> 模型每圈出 100 个"高潜留存用户"，其中**72 个真的留到了 7 日**（基线只有 18.6%），准确率**接近 4 倍**。

> 面试话术：*"我特意看了 Accuracy，0.871 看起来不错，但全猜流失就有 0.814，信息量为零。所以在 18.61% 正样本率的极端不平衡场景下，我以 PR-AUC 和 Recall 为主指标，Accuracy 只作参考。"*

### 5.6 特征重要性

| 特征                     | 重要性        | 解读                       |
| ---------------------- | ---------- | ------------------------ |
| **`log_rounds`（游玩深度）** | **0.3786** | **最强预测因子**               |
| `bucket_ord`（深度等级）     | 0.2811     | 次强                       |
| `rounds_gt_50`         | 0.2075     | 重度阈值信号                   |
| `rounds_gt_20`         | 0.0996     | 中度阈值信号                   |
| `retained_1`（次日留存）     | 0.0294     | 弱                        |
| **`played_any`**       | **0.0020** | 几乎无信息                    |
| **`version_gate_40`**  | **0.0020** | **分组无预测力（与 Model A 一致）** |

**逻辑回归系数（可解释视角）**：

| 特征                | 系数          | 解读             |
| ----------------- | ----------- | -------------- |
| `log_rounds`      | **+2.1689** | **最强正向因子**     |
| `bucket_ord`      | +0.1096     | 正向             |
| `played_any`      | **-0.3832** | **负向（异常）**     |
| `rounds_gt_20`    | -0.1219     | 条件效应，非单变量含义    |
| `retained_1`      | -0.0347     | **共线性导致符号翻转**  |
| `version_gate_40` | -0.0384     | 分组影响很小，与因果结论一致 |

**必须诚实解释的两个"反直觉系数"**：

1. **`played_any` 为负**：是因为 `played_any` 与 `log_rounds` 高度共线（只要玩了轮次就 > 0）。在 `log_rounds` 已捕获全部信息后，`played_any` 的边际贡献为负。**共线性下的系数不可直接解读。**
2. **`retained_1` 为负**：同理，`retained_1` 与 `bucket_ord` 高度相关。多重共线性（multicollinearity）导致符号翻转。

> **正确做法**：用 VIF（方差膨胀因子）检验共线性，或用**条件重要性**（conditional importance，如 SHAP）而非**边际重要性**。这是本项目可改进的明确方向。

> 面试话术：*"梯度提升树的特征重要性清晰——游玩深度 log_rounds 占 0.3786，是最强因子。但逻辑回归里 played_any 和 retained_1 出现了反直觉的负系数，我不会强行解读，而是识别出这是共线性：只要玩了就有轮次，played_any 与 log_rounds 几乎完全共线，其边际贡献在 log_rounds 已解释后必然接近 0 甚至为负。正确做法是看条件重要性（SHAP）或检验 VIF，这也是我后续会改进的方向。"*

**Lift 定义**：

```
Lift(p) = Precision@p / Overall_Precision
        = Precision@p / 0.1861
```

**Lift = 4.11 的业务翻译**：

> 只投放前 10% 的用户，效率是随机投放的 **4.11 倍**。

| 投放 Top  | 用户数       | 捕获留存用户    | 捕获率        | **Lift**  | **Precision** |

| 20%     | 4,510     | 1,641     | 66.32%     | 3.32x     | 61.69%        |

| 50%     | 11,274    | 2,761     | 93.25%     | 1.87x     | 34.70%        |

### 5.8 【延伸】为什么不直接用回归算效应

有一个更"因果"的替代方案：把 `retained_7 ~ version` 的**逻辑回归系数**作为因果效应估计，效率高得多：

| 方法       | 效应量             | 优点                  | 缺点          |
| -------- | --------------- | ------------------- | ----------- |
| Z 检验     | −0.008217       | 能算CI、能算功效           | 只给点估计       |
| **回归系数** | **约 −0.0402**   | 能算 CI、能调整协变量、支持连续指标 | 依赖线性/对数线性假设 |
| 逻辑回归系数   | −0.0384（未控制协变量） | 可解释为对数几率差           | 模型设定依赖强     |

**这实际上是行业标准做法**——RCT 的标准分析就是回归：

```
Y_i = α + β · T_i + γ · X_i + ε_i
```

`Y` 用留存（0/1）→ **线性概率模型**；`Y` 用 ARPU / 轮次 → **OLS**

**为什么本项目仍用 Z 检验**：Z 检验是比例型指标**最直接、最透明、无需模型设定**的方法，且能配合 Bootstrap / 贝叶斯做交叉验证。**回归作为交叉验证更佳。**

> 面试话术：*"如果做一次严谨的补充，我会用 Y = α + β·T + γ·X 的回归框架替代 Z 检验。这样做的好处是可以直接调整协变量（新用户画像、渠道等），并同时估计置信区间。本项目因为缺少协变量字段，用 Z 检验更透明，但我会把回归作为交叉验证方案写入改进计划。"*

### Q1（★）用三分钟介绍这个项目

**答**：

> 这是一个基于真实线上数据的游戏 A/B 实验分析项目。业务背景是三消游戏 Cookie Cats 想把第一个关卡门从第 30 关后移到第 40 关，用 9 万名真实玩家的随机分组数据验证这个改动该不该上线。
>
> 我的工作分六层：先建指标体系（定7 日存留为北极星）；再数据质量检查（含 SRM 检验，确认分流健康）；然后做留存归因（对比 + 漏斗 + 6 层分层下钻）；核心是统计检验，用双比例 Z 检验、Bootstrap、贝叶斯三条独立路径交叉验证；再用逻辑回归和梯度提升树建流失预测模型做落地分層；最后给业务决策建议。
>
> **结论是不上线**：7 日留存从 19.02% 降到 18.20%，p = 0.0016，Bootstrap 和贝叶斯都给出 99.92% 的支持度，Bonferroni 校正后依然显著。归因上我做了分层，发现伤害不是均匀的，而是集中在 21 到 100 轮的中度玩家身上，重度玩家完全不受影响——因为只有刚好卡在关卡门附近的玩家才会被这个改动直接影响。这个洞察把建议从"调整关卡门"细化成"针对中度玩家做破冰激励"。

### Q2（★）这个项目最大的收获是什么

**答**：

> 最大的收获是建立了"不显著≠无差异"的意识。我做了统计功效分析：1 日留存不显著（p=0.074），但它的功效只有 42.8%，远低于 80% 的标准，所以这个"不显著"只能解读为证据不足，而不是"改动对 D1 无害"。而 7 日留存功效 88.4%，它的显著结论才可信。
>
> 这意味着在 A/B 实验里，看到 p>0.05 时第一反应不应该是"没差异"，而是"我有没有足够的能力检测到差异"。这直接决定了结论能不能被信任。

### Q3（★）为什么 7 日留存做北极星，不看 ARPU？

**答**：

> 因为数据集里**没有内购金额字段**，无法计算 ARPU 和 LTV，所以这不是我的偏好而是数据约束。
>
> 但我意识到这构成本项目最大的局限：这次实验的争议本质是"留存 vs 变现"的权衡，而我只覆盖了留存这一边。所以我的结论严格来说是"从留存侧看不该上线"，而不是"综合权衡后不该上线"。
>
> 完整的判断逻辑应该是"Δ留存 × LTV > ΔARPU × 变现提升"才值得上线。数据缺了 ARPU 这一半，我在报告里明确标注了这个边界。面试时我觉得**主动说清局限比假装全面更可信**。

### Q4（★★）你怎么保证数据可信？

**答**：

> 我做五层校验：
>
> 1. **SRM 检验**（最关键）：两组 49.57% vs 50.43%，卡方 p=0.70，分流系统健康。如果 SRM 不通过，后面的检验全部无效——这是实验系统的第一号红线。
> 2. 主键唯一性：userid 无重复
> 3. 取值合法性：version 仅两个值，retention 仅 True/False
> 4. 分布检查：轮次右偏长尾（均值52、中位数17、P90=135），我**不删异常值**而是描述分布并做log 变换，因为删数据会引入选择偏差
> 5. 交叉验证：Z 检验与卡方检验结果一致（χ² = Z²），三条独立路径同向

### Q5（★★）如果实验组和对照组人数差很多，怎么办？

**答**：

> 先查是不是 SRM。如果是系统 bug，要修数据而不是分析数据。
>
> 如果是真实随机波动（比如 5:5 分流但实际 47:53），样本量不等是可以接受的，Z 检验本身就支持不平衡样本（用合并标准误）。
>
> 但要注意：**如果一边掉了 5% 的数据**，就要排查这个缺失是否与分组相关——比如 gate_40 组某个版本的埋点失败。这时的差异可能被系统性放大或缩小。
>
> 补救手段：先做**样本量加权**，或在漏斗分析里检查各环节的组间流失率是否一致。

## B. 统计检验类

### Q6（★★）p 值到底是什么意思？

**答**：

> p 值是在**原假设成立的前提下**，观测到当前结果或更极端结果的概率。
>
> 本例 p=0.0016 的准确含义是：**假如两组留存率真的完全相同，那么在 9 万人的样本量下，还能观测到 0.82pp 以上差异的概率只有 0.16%。** 因为这么低，我们拒绝"改动无效"这个假设。
>
> 最常见的错误理解是把它当成"原假设为真的概率"。实际上 p 值是一个**条件概率**——条件是"假设 H0 为真"，结论是"观测到这种极端数据的概率"。

### Q7（★★）显著就一定重要吗？

**答**：

> 不一定，这是核心陷阱之一。
>
> 本项目正好撞上了这个矛盾：7 日留存的 Cohen's h = 0.0211，在统计学上属于"可忽略"的小效应，但业务上是 0.82pp 的北极星指标下降，百万级流量下就是 8,200 个留存用户，完全不可接受。
>
> 我的处理逻辑是：**统计显著性回答"是不是真的"，决策依据是"是否超过业务可承受阈值"。** 在北极星指标上，任何显著的负向都直接否决，无论效应量多小。效应量在这里的作用是辅助判断幅度。
>
> 反向的例子是：差异 5pp 但 p=0.06，业务上极重要但统计上没过线。这种情况正确做法是**加长实验提高样本量**，而不是降低标准。

### Q8（★★）置信区间怎么读？跨 0 意味着什么？

**答**：

> 95% CI = [0.312pp, 1.328pp]，读法是"我们 95% 确信真实差异落在这个区间"。
>
> 判断规则看 CI 和 0 的关系：
>
> - 完全在 0 右侧 → 显著正向，上线
> - 完全在 0 左侧 → 显著负向（本例），不上线
> - 跨 0 → **无法拒绝 H0**
>
> **关键认知：跨 0 不代表"两组一样"，只代表"我们无法区分"。** 要区分这两者，必须报告 CI 的宽度。本例 D7 的 CI 宽度 1.016pp，D1 的宽度 1.3pp 且跨 0，精度更差、结论更弱。
>
> 所以我加做了功效分析来补足：CI 跨 0 + 功效高 → 可以说"确认无实质差异"；CI 跨 0 + 功效低 → 只能说"证据不足，需继续采样"。

### Q9（★★）为什么要做 Bootstrap？

**答**：

> 因为参数化检验依赖分布假设，而我们的数据不满足。
>
> 轮次是右偏长尾分布（均值 52，中位数 17，差 3 倍），对均值做 Z 检验本身脆弱。Bootstrap 直接把数据当成分布的唯一来源，通过有放回重抽样 10,000 次模拟采样分布。
>
> 它最大的价值是**可以给任何统计量做区间估计**——中位数、分位数、偏度，这些非均值指标 Z 检验完全做不了。
>
> 局限有两个：第一，Bootstrap 只能给 CI，**给不了 p 值**（除非做null bootstrap——先按 H0 变换数据再重抽样）；第二，计算量大 100 到 1000 倍。
>
> 本例Bootstrap 结果 CI=[0.325, 1.344]，与 Z 检验的 [0.312, 1.328] 几乎一致，说明结论对方法选择不敏感。

### Q10（★★）为什么还要做贝叶斯？它和频率派区别在哪？

**答**：

> 核心区别是**输出形式**。频率派输出 p 值，回答"差异是否为 0"；贝叶斯输出概率，回答"我该怎么做决策"。
>
> 业务方看不懂 p=0.0016，但能直接理解"有 99.92% 把握第 30 关更好"。
>
> 技术上，比例型指标用 Beta-Binomial 共轭：先验 Beta(α,β) + 二项数据 → 后验 Beta(α+k, β+n−k)。本例对照组后验是 Beta(8503, 36199)，均值 19.021%。我做了 20 万次蒙特卡洛采样估计后验分布。
>
> **最关键的一个发现**：贝叶斯的 95% 可信区间 [0.312, 1.327] 和频率派的 95% CI [0.312, 1.328] **几乎完全一致**。这说明结论极度稳健——两条完全不同的数学路径给出相同答案。
>
> 这背后是 **Laplace 法则**：样本量足够大时先验几乎不影响后验，4.5 万的样本量下，弱信息先验 Beta(1,1) 的影响被数据完全淹没。贝叶斯优势真正显现是在小样本、多指标、连续实验场景。
>
> 局限是 Beta-Binomial 只适用于二项型比例指标，轮次这类连续长尾指标需要 Normal-Inverse-Gamma 或 Gamma-Poisson。

### Q11（★★★）第一类错误和第二类错误，哪个更严重？

**答**：

> 第一类错误（假阳性，α）是"H0为真却拒绝"，在A/B 实验里意味着**无效改动被判为有效并全量上线**，伤害全部用户。
>
> 第二类错误（假阴性，β）是"H0 为假却未拒绝"，意味着**有效改动被判为无效，团队错失机会**。
>
> **这两者的代价是高度不对称的**：Retention 掉 0.82pp 是 9 万玩家不可逆的损失，而漏掉一个正向改动只是少赚一点。所以实验设计必须**宁枉勿纵**——这就是 α 普遍取 0.05甚至更严的原因。
>
> 我的具体做法：α = 0.05 作为基础门槛，同时因为测了 3 个指标，额外做 Bonferroni 校正到 0.0167。D7 的 p=0.00155 依然通过，说明核心结论对保守校正稳健。
>
> 反过来也要警惕：如果改动收益极小而样本量不足，β 就会很高，这时候不该用"没显著"来否决一个微小正向改动，而应该算 MDE 看需要多少样本。

### Q12（★★★）MDE 和统计功效是什么？为什么它们比 p 值更重要？

**答**：

> MDE 是最小可检测效应，Power 是统计功效（真实有差异时能正确检测的概率），标准要求≥80%。
>
> **它们比 p 值重要，因为它们回答的是"我的结论可信吗"，而 p 值只回答"差异是不是噪声"。**
>
> 本项目是最好的例证：
>
> - D7 留存：MDE = 0.741pp，观测效应 0.0211，功效 **88.4%** → 效应大于 MDE，样本量充足，**显著结论可信**
> - D1 留存：MDE = 0.933pp，观测效应 0.0119，功效 **42.8%** → 效应小于 MDE，**样本量根本不足以检测到 0.59pp 的差异**
>
> 所以D1 的"不显著"只能解读为"本研究无法检测到 D1 差异"，绝不能解读为"改动对 D1 无害"。这两个结论看起来只差几个字，但一个是专业一个是外行。
>
> 提高功效有四个杠杆：加大样本量（SE ∝ 1/√n）、提高 α、降低 MDE 要求、以及**方差缩减（CUPED）**。其中 CUPED 性价比最高——用实验前协变量预测 Y，残差方差减少 50% 相当于样本量翻倍，且不增加实验成本。

### Q13（★★★）为什么要做多重比较校正？Bonferroni有什么问题？

**答**：

> 因为存在"分析师的诅咒"：测 20 个指标，即使全部无效，至少一个显著的概率是 1−0.95²⁰ = **64.2%**。指标越多，假阳性越多。
>
> Bonferroni 把 α 除以指标数，本例 0.05/3 = 0.0167。D7 的 p=0.00155 依然显著，结论稳健。
>
> **Bonferroni 的缺点是最保守**，因为它假设所有检验都独立且同时需要控制，实际损失统计效力（power）。指标多的时候我会用 **Benjamini-Hochberg** 控制 FDR（错误发现率 = 假阳性/全部显著数），效力更高。
>
> 顺便说，多层嵌套指标其实**不需要校正**——因为 D1、D7、轮次是**同一决策的不同侧面**，不是"如果显著就想做"的多个独立机会。但如果你要挑"最好的那个指标上线"，就必须校正。这是我做 Bonferroni 的理由。


### Q14（★★★）Mann-Whitney U 检验和 t 检验的区别？

**答**：

> 最本质的区别是检验对象不同：
>
> - **t 检验**：检验**均值**是否相等
> - **Mann-Whitney U**：检验**分布位置**，等价于问"随机抽一个实验组玩家和一个对照组玩家，谁的值更大"的概率
>
> 它基于**秩和**：把两组合并按数值排序，比较排名之和。零假设是"两组的分布相同（即随机标签与分组无关）"。
>
> 本例轮次右偏严重（均值52 中位数17），均值检验不稳健，所以用 U 检验：U = 1,024,331,250，p=0.0502，**恰好卡在边界**。
>
> 我对这个结果的解读是诚实的：均值下降 1.16 轮方向上确实是实验组更差，但证据不足以在 95% 水平断言显著。这是诚实的不显著结论，不是硬凑。

### Q15（★★★）为什么用 Beta 分布做先验？共轭是什么意思？

**答**：

> 因为比例型指标是二项分布，而 **Beta 是二项分布的共轭先验**。共轭的含义是"先验和似然是同一族分布，相乘后仍是同一族"，所以后验可以直接写出解析式，不用做 MCMC 采样。
>
> 具体来说：Beta(α,β) + Binomial(k,n) → Beta(α+k, β+n−k)。而且 Beta 分布的均值方差有解析式：E[p]=α/(α+β)，Var[p]=αβ/[(α+β)²(α+β+1)]。所以后验的均值是 (α+k)/(α+n)，方差也可以直接算。
>
> 本例对照组后验 Beta(8503, 36199)，均值 = 8503/44702 = **19.021%**，和观测值 19.02% 几乎一样——因为样本量大到先验可忽略。
>
> **但共轭先验也有代价**：选 Beta 先验隐含假设数据是二项分布（每次独立、成功率不变）。如果玩家之间有网络效应（互相影响），这个假设就不成立了。

### Q16（★★★）置信区间为什么用非合并标准误，而 Z 检验用合并的？

**答**：

> 因为两者的逻辑目标不同：
>
> **Z 检验做的是假设检验**，在 H0 成立时两组共享同一个真实比例 p，所以用 **pooled SE**（把两组信息合并估计），这样能减小方差、提升检验力。
>
> **置信区间是对真实差异的无偏估计**，不依赖 H0 假设成立，所以用 **unpooled SE**（各组各自估计），更保守也更准确。
>
> 如果偷懒用同一个 SE 算 CI，会**低估区间宽度**，导致过度自信——你会以为自己比实际上更确定。这是实务中很常见的 bug。

### Q17（★★★）你为什么用三种方法验证？会不会是过度设计？

**答**：

> 我认为这是必要的，核心理由是**鲁棒性论证**。
>
> 三种方法的假设完全不同：Z 检验依赖大样本正态近似，Bootstrap 不依赖任何分布假设，贝叶斯依赖显式先验。如果三者结论一致，说明结论**对方法选择不敏感**，无法被任何一种方法的局限推翻。
>
> 这不是"堆技术"，而是**用独立路径排除单一方法的实现 bug 或假设失效**。特别是我同时跑了卡方检验，发现 χ² = Z² = 10.01 完全一致，这就是交叉验证的价值——它证明我的实现逻辑没有偏差。
>
> 如果只做一种方法，面试官问"你怎么知道不是你代码写错了"，我很难回答；但做了三条路径，这个问题就不存在了。

### Q18（★★）为什么不直接做 A/B = 两组均值 t 检验？

**答**：

> 因为留存率是**比例型指标**，不是正态连续变量。均值 19% 意味着每个玩家的取值只能是 0 或 1，分布是二项分布而非正态分布。
>
> 对于比例型指标，标准做法是双比例 Z 检验或卡方检验。t 检验虽然在大样本下渐近可用，但效率更低且假设不匹配。
>
> 什么时候用 t 检验？当指标是**连续型**（ARPU、观看时长），或者你要做的是**回归系数估计**（把分组当自变量放进回归，β 就是因果效应估计）。实际上回归框架（RCT 标准分析）更通用，可以同时调整协变量，我把它写进了改进计划。

## C. 机器学习类

### Q19（★）Accuracy 0.87 是不是很高？

**答**：

> 这是最经典的陷阱。**全猜"流失"就有81.39% 的准确率**，因为正样本率只有 18.61%。模型的 87.13% 只比这个基线高 5.7pp。
>
> 更致命的是 Model A 的混淆矩阵：TP=0, FP=0, FN=4195, TN=18353。它预测一个人都不留存，准确率 81.4%，**但信息量为零**。
>
> 所以在极端不平衡场景下，我以 **PR-AUC 和 Recall** 为主指标。PR-AUC 0.683，Precision 0.718，业务含义是"每圈出 100 个高潜用户，其中 72 个真的留到了 7 日"，是基线的 3.9倍。

### Q20（★★）为什么用 PR-AUC 而不是 ROC-AUC？

**答**：

> 因为**FPR 的分母太巨大，会让 ROC-AUC 失真**。
>
> 本例负样本有 75,992 人，即使误报 836 个，FPR 也只涨 1.1%。所以 ROC-AUC 看起来会很高，但它没有反映"误报很多"这个事实。
>
> 极端例子：负样本 100 万人，即使误报 10 万个，FPR 也只有 10%，ROC-AUC 依然漂亮，但 Precision 已经崩了。
>
> **PR-AUC 直接聚焦误报成本**，在正样本率 18.6% 的场景下更能反映模型的实用价值。

### Q21（★★）模型 AUC 都一样，还要上GBDT 吗？

**答**：

> 三个模型 AUC 几乎相同（0.888），说明**数据量足够，模型的复杂度不是瓶颈**。这是个好消息，说明结论不依赖特定模型选择。
>
> 但我还是选了 GBDT，因为：
>
> 1. **AUC 略高**（0.8885vs 0.8880）
> 2. **Precision 最高**（0.7181 vs 0.7116）
> 3. **不依赖线性假设**，能自动捕捉非线性交互（比如"轮次的某个特定区间影响特别大"这类模式）
>
> 工程上还有一点：CV AUC 均值 0.8886、标准差仅 0.0019，说明**泛化稳定、无过拟合**。如果 CV 和训练 AUC 差距很大，那才是过拟合信号。

### Q22（★★）逻辑回归里 played_any 系数是负的，怎么解释？

**答**：

> 我不会强行解读，因为这是**多重共线性**导致的。
>
> 只要玩家玩了游戏，`played_any` = 1，`log_rounds` 一定 > 0。这两个特征携带几乎完全相同的信息，相关系数接近 1。在 VIF 高的情况下，回归系数是不稳定的，符号可以任意翻转。
>
> 证据：`played_any`（-0.3832）和 `retained_1`（-0.035）都是负的，但`log_rounds` 是强正的 +2.1689。而 GBDT 的**边际重要性**里 played_any 只有 0.002、retained_1 只有 0.029，两者都接近无信息——这印证了共线性判断。
>
> 正确做法：用 VIF 检验共线性，或直接看**条件重要性**（SHAP / permutation importance）而不是边际重要性。这是我明确记录的改进方向。

### Q23（★★★）你的流失预测模型有数据泄漏吗？

**答**：

> **有，而且是明确的泄漏，我主动标注了。**
>
> 特征 `sum_gamerounds` 是安装后 **14 天累计**轮次，而标签是**第 7 天**是否留存。我用 7 天之后的行为去预测第 7 天的结果，这在时间上是穿越的。
>
> 这会让模型在离线评估时虚高（AUC 0.888 里有一部分是这个泄漏贡献的），生产环境中无法复现。
>
> **正确做法**：模拟生产场景，用决策时点之前的快照。比如预测 D30 留存只用前 14 天特征。我把它写成 P3 改进建议了。
>
> 面试时我更愿意主动说这个，因为它体现的是"我知道我的模型的边界在哪"。这种意识比模型分数高0.001 更值钱。

### Q24（★★★）Lift = 4.11 是什么意思？怎么用它做决策？

**答**：

> Lift 衡量的是**投放效率倍数**：
>
> ```
> Lift(p) = Precision@p / 全量基线精度
>        = 0.765 / 0.1861 = 4.11
> ```
>
> 业务翻译：**只投放前 10% 的用户，效率是随机投放的 4.11 倍。**
>
> 决策用法：假设总激励预算 100 万份。随机投放只能换来 18.6 万留存；精投前 10% 能换来 76.5 万留存；精投前 30% 覆盖 80.4% 的留存用户。
>
> 所以我会分场景：稀缺资源（高价值礼包）投前 10%；批量召回（push）投前 30%，因为覆盖 80% 的成本比覆盖 100% 低得多。

### Q25（★★）Model A 的 AUC 只有 0.51，为什么还要做这个模型？

**答**：

> 这是我刻意设计的**零信息基线**。
>
> 假设我们已经在 2.x 章证明分组对留存有因果影响，那"分组能不能预测留存"？答案是几乎不能（AUC 0.51 ≈ 随机）。
>
> 这不矛盾——**群体效应≠ 个体预测**。因果上分组改变了总体留存率，但两组个体的留存概率高度重叠，无法从"他是gate_40"推断"他会不会留存"。
>
> 这个模型的作用是**排除泄漏**：如果Model B的 AUC 是 0.888而 Model A 是 0.51，就证明 0.888 来自行为特征，而不是 version 这个变量偷看了答案。如果不设这个基线，评审时一定会有人问"你的AUC 是不是靠分组刷出来的"。

## D. 业务理解类

### Q26（★★）为什么 1 日留存不显著，7 日显著？

**答**：

> 这恰恰是我做时间维度拆解的核心洞察，说明**伤害是累积的，不是即时的**。
>
> 逻辑是：人均 51 轮，很多玩家 14 天内根本打不到第 30 关，所以门槛后移对**第 1 天的体验完全没影响**——他们还没触碰到这个机制。
>
> 但到了第 7 天，玩家的新鲜感被前移的体验节奏消耗掉了一部分，而且关卡门制造的那个"回访动机"被往后推了 10 关的距离，削弱了回访粘性。
>
> **业务翻译**：关卡门的作用不是"卡住玩家"，而是**制造回访动机**（我的体力还没攒满，回去吧）。后移门槛就是把这个动机往后推，短期无损、长期削弱。
>
> 如果是"产品体验变差"，D1 就会立刻掉。所以 D1 不显著 + D7 显著这个组合，恰好排除了"体验即时变差"这个假设。

### Q27（★★）为什么报告里的 CI 是 [0.312, 1.328]，而 JSON 里bootstrap 是 [0.325, 1.344]？

**答**：

> 两个是不同方法的置信区间，报告里展示的是主检验 Z 检验的 CI。
>
> Z 检验用非合并标准误，Bootstrap 用经验分位数。两者相差约 0.013pp，在1pp 量级上是 1.3% 的相对差异，完全在蒙特卡洛误差和统计近似允许的范围内。
>
> 这恰好说明两条路径是**相互验证且各有微小方法误差**的。如果它们差很多，我反而要担心代码有问题。

### Q28（★★）为什么用 p = 0.0016 就拒绝上线？万一它是偶然呢？

**答**：

> 三层保障：
>
> **第一层：p 值本身**。p = 0.0016 意味着即使真的没差异，观测到这么大差异的概率只有 0.16%。
>
> **第二层：三条独立路径**。Z 检验、Bootstrap（10,000 次重抽样）、贝叶斯（40 万次采样）结论完全一致，三种方法的假设完全不同，一致就说明不是单一方法的偶然。
>
> **第三层：多重比较校正**。测了 3 个指标，Bonferroni 校正到 α=0.0167，p=0.00155 依然通过。
>
> **另外还有一个业务侧的支撑**：分层归因给出了清晰的机制解释——伤害集中在 21-100 轮的中度玩家，正是被后移门槛直接影响的那一群人。**统计显著 + 机制可解释 + 结论可落地**，这三条同时成立才敢下决策。

### Q29（★★）这个实验有什么局限性？

**答**：

> 我在报告里明确列了三条：
>
> 1. **缺变现字段**：没有内购金额，无法算 ARPU/LTV。而这次实验的核心争议就是"留存 vs 变现"的权衡，所以我只覆盖了一半。
> 2. **缺归因维度**：没有渠道、机型、地域字段，做不了更细粒度的流失归因。
> 3. **观测窗口只有 14 天**：无法评估 D30 及以上的长期影响。而我发现的"累积伤害"效应，恰恰说明长期影响可能更严重。
>
> 加上我自己发现的一条：  
> 4\. **建模时间泄漏**：流失预测模型用了 14 天累计轮次预测 D7 留存，存在时间穿越，离线指标会虚高。
>
> 第 4 条我列为 P3 改进项。

### Q30（★★★）如果产品经理说"p值这么小，会员明显提升，麻烦上线"，你怎么回？

**答**：

> 我会把对话拉回到**分层视角**，因为这个 p 值是总体差异，不等于每个层都变差。
>
> 分层数据告诉我：0-20 轮层是**正向的**（+0.15pp），100 轮+ 层是**几乎没影响**（-0.15pp），真正受损的是 21-100 轮层（-1.51到 -4.78pp）。
>
> 所以正确的讨论不是"上不上"，而是"**能不能只对 21-100 轮玩家上这个改动**"。这才是这份分析真正的价值——从一个"要不要上线"的二元决策，变成了"能不能做定向灰度"的精细化决策。
>
> 这也是分层分析的意义：总体的 p 值告诉你"有问题"，分层告诉你"问题在哪"。

## E. 综合开放题

### Q31（★★）你怎么看待 A/B 实验在业务中的价值？

**答**：

> A/B 实验最大的价值不是"证明改动有用"，而是**让组织用低成本获得确定性**。
>
> 没有实验的时代，一个决策靠的是"谁的嗓门大"或"谁的职位高"。有了实验，决策依据变成 p 值和置信区间——虽然只有 5% 的显著性，但它的价值在于**排除了 95% 的猜测空间**。
>
> 我在这个项目里体会最深的其实是**反向价值**：结论是"不上线"，也就是**拦住了一个看起来很合理的提案**。"让玩家多玩 10 关"这个直觉听起来天然正确，但数据说它伤害了 7 日留存。如果靠拍脑袋上线，这个损失会持续存在，而且因为上线后指标下跌会被归因成"版本更新没做好"，很难被追溯。
>
> 所以我觉得 A/B 实验最强大的地方是：**它给了一个可以事后审计的决策记录。**

### Q32（★★★）如果让你重做一遍，你会怎么改进？

**答**：

> 五点改进，按优先级：
>
> **1. 补充 ARPU / 变现字段**（最重要）。这次实验的争议本质是留存 vs 变现，只有留存这一半的结论是不完整的。有了变现数据才能算LTV，做完整的权衡。
>
> **2. 预注册（Pre-registration）**。在实验开始前就固定主指标（7 日留存）、样本量目标和分析计划，防止看到结果后再选指标（p-hacking）。如果能做预注册，7 日留存作为北极星的论证就更硬了。
>
> **3. 引入 CUPED 方差缩减**。用安装前的历史数据（如前一天的活跃度）作为协变量，方差可以减半，等价于样本量翻倍，却不增加实验成本。
>
> **4. 修复时间泄漏，重建流失预测模型**。用 T-1 快照特征重训，让离线指标能反映真实生产表现。
>
> **5. 加分层异动监控**。既然伤害集中在 21-100 轮，那实验期就应该按这个维度做实时监控，而不是等14 天后才发现。

### Q33（★）这个项目用到哪些技术栈？

**答**：

> Python 全流程：pandas做数据处理，NumPy 做数值计算，SciPy 做假设检验（Z 检验、卡方、Mann-Whitney U），statsmodels 做统计功效分析（NormalIndPower）和效应量计算（proportion_effectsize），scikit-learn 做建模（逻辑回归、随机森林、GradientBoosting），Matplotlib 做可视化，另有 DuckDB 执行 SQL 版的指标计算。输出层用了 HTML + ECharts 做交互式报告。
>
> 全流程用 `run_all.py` 一键跑通，配置了固定随机种子（seed=42）保证结果可复现。

## 版本一：详版（推荐用于简历「项目经历」栏）

**项目名称：** 手游《Cookie Cats》关卡门槛 A/B 实验分析与留存归因  
**项目类型：** 独立数据分析项目 · 真实线上实验数据 · 90,189 名玩家  
**技术栈：** Python · pandas · NumPy · SciPy · statsmodels · scikit-learn · DuckDB · Matplotlib · ECharts

**项目背景**  
Tactile Entertainment 旗下三消手游 Cookie Cats 计划将首个关卡门从第 30 关后移至第 40 关，以延长新手连续体验。该改动存在「留存 vs 变现」权衡争议，需基于 9 万名真实玩家的线上随机分组数据，判断是否上线。

**核心工作与成果**

1. **指标体系建设**：设计「北极星（7 日留存）— 一级（1 日留存、人均轮次）— 二级（0 轮占比、漏斗转化）— 分层维度」四层指标体系，明确决策口径与唯一拍板指标。
2. **数据质量与实验有效性校验**：执行 SRM 检验（两组 49.57%:50.43%，χ²检验 p=0.70）、主键唯一性、取值合法性、分布异常共 5 类校验；针对轮次右偏长尾特征（均值 52.46 / 中位数 17）采用 log 变换与非参数检验，**拒绝删异常值以避免选择偏差**。
3. **统计检验（三路径交叉验证）**：
   - 双比例 Z 检验：7 日留存 19.02% vs 18.20%，Z=3.16，**p=0.0016**，95% CI [0.31, 1.33] pp
   - Bootstrap 重抽样 10,000 次：99.92% 支持对照组，CI [0.33, 1.34] pp
   - 贝叶斯 Beta-Binomial 后验（40 万次采样）：**P(对照组更优)=99.92%**，可信区间 [0.31, 1.33] pp 与频率派高度一致
   - 卡方检验交叉验证（χ² = Z² = 10.01），确认实现无偏差
   - 3 指标多重比较，**Bonferroni 校正后 α=0.0167，结论仍显著**
4. **统计功效分析（关键方法论）**：计算 MDE = 0.741pp，7 日留存实测功效 **88.4%**（样本量充足，显著结论可信）；1 日留存功效仅 **42.8%**，据此明确「D1 不显著」应解读为**证据不足**而非「无差异」，避免了一次典型的误读。
5. **分层归因（核心洞察）**：按游戏深度 6 桶下钻，发现留存损失呈 **S 型分布**，且**不均匀**——伤害集中于 **21-100 轮中度玩家**（51-100 轮层差异 **-4.78pp**，占玩家 31.5%），而0-20 轮（+0.15pp）与 100 轮+ 层（-0.15pp）几乎不受影响。机制解释为：仅"刚好卡在关卡门附近"的玩家被直接影响，识别出 **Simpson 悖论**导致的整体稀释效应。
6. **流失预测建模**：构建 7 特征体系（含 log 变换、阈值哑变量、有序等级），对比逻辑回归 / 随机森林 / GBDT 三模型。**AUC 0.8885、PR-AUC 0.683、CV AUC 0.8886±0.0019（无过拟合）**。刻意设置「仅实验分组」基线模型（AUC 0.5103），证明预测力完全来自行为特征而非分组泄漏，验证**群体因果效应 ≠ 个体预测能力**。
7. **业务落地（Lift 分析）**：前 10% 高潜用户覆盖 **41.12%** 的留存用户，**Lift = 4.11x**，Precision 达 **76.5%**（基线 18.6%）；前 30% 覆盖 80.38%。为「新手激励/召回推送」提供分层投放依据，投放效率提升 4 倍。

**核心结论**  
改动使 7 日留存显著下降 **0.82pp（相对 -4.51%）**，三法一致支持拒绝上线（误判风险约 0.08%）。量化业务影响为**每百万新玩家损失约 8,200 名 7 日留存用户**。基于分层洞察提出替代方案：用「破冰激励」替代「后移门槛」，聚焦 21-100 轮中度玩家；同时排查 0 轮次玩家（占 4.4%，7 日留存仅 0.83%）的买量渠道质量。

**成果输出**

- 单文件交互式 HTML 分析报告（12 张图表 + 完整方法论说明与局限声明），可直接部署 GitHub Pages 供团队查阅

## 版本三：STAR 口述版（面试现场用）

**S（情境）**  
游戏公司想把首个关卡门从 30 关挪到 40 关，直觉上能让玩家玩得更久。但这个改动有明显争议——更早触达付费墙意味着变现机会延后。团队需要一个可靠的数据结论来决定上不上。

**T（任务）**  
基于公司真实线上 A/B 实验数据（9 万名玩家，14 天窗口），独立完成全链路分析，判断是否上线，并给出可落地建议。

**A（行动）**

1. 先建指标体系，把 7 日留存定为唯一北极星，避免上线后该看哪个数之争。
2. 做 5 类数据质量校验，重点是 SRM 检验确认分流系统健康（p=0.70）。
3. 统计上不只跑一种检验，而是用Z 检验、Bootstrap、贝叶斯三条独立路径交叉验证，再用卡方核对实现逻辑。
4. **做了功效分析**，发现 1 日留存不显著是因为功效只有 42.8%，因此明确说"证据不足"而不是"无差异"。
5. 分 6 层做归因下钻，发现伤害高度不均匀，集中在 21-100 轮中度玩家。
6. 建模做落地分層，得到 Lift 4.11x 的投放效率提升。

**R（结果）**  
结论：**不上线，保留 gate_30**。7 日留存下降 0.82pp（p=0.0016），三法一致支持度 99.92%，Bonferroni 校正后稳健。每百万新玩家损失约 8,200 名 7 日留存用户。  
分层洞察把建议从"调整关卡门"细化为"只针对 21-100 轮玩家做破冰激励"，从二元决策变成可定向灰度的精细化决策。输出交互式报告供团队使用。
